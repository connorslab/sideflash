# Development fixture checks

Use Python 3.12 in an isolated virtual environment:

```sh
python -m pip install -r tests/requirements.txt
python tests/verify_vectors.py
```

The frozen vectors use public test keys and expired validity intervals. They are
not payable addresses. Rust generates the fixtures and consumes the same saved
bytes in its unit tests. Python independently checks the Bech32m checksum,
canonical CBOR, fixture identity and native address bytes, BOLT12 byte extraction,
BIP340 signatures, validity and modified signed fields. It also creates QR
images and decodes them with ZXing.

This checker trusts the expected recipient key in each fixture. It is not a
general native-policy validator, full BOLT12 verifier or production payment
client. Tests use assertions: do not run Python with optimization enabled.

`qr-report.json` records synthetic results. It is not evidence of camera
performance, hostile-image tolerance or independent human security review.

## Compact v1

Run `python tests/test_compact_v1.py` for six test groups covering both v1
fixtures, all signed-field mutations, canonical representation, wrong networks,
invalid validity/authority, version separation, size limits and eight synthetic
QR round-trips. `qr-report-v1.json` is regenerated by this test.

`compact_v1.py` is a fixture codec, not a general native-policy/BOLT12 validator.
It relies on independently supplied fixture authorities and expected offer bytes.
It does not replace the production policy, offer-feature or chain validators.
Both Rust feature branches now verify the frozen v1 fixtures and preserve v0
decoding. Do not describe this as independent human review or a deployed release.

`generate_v1_vectors.py` reproducibly re-signs the frozen v0 fixtures with their
known test secrets (repeated 01, 02 and 03 bytes), using zero BIP340 auxiliary
randomness for deterministic test output. Never use those keys for money.
Legacy v0 vectors and checks remain unchanged.
